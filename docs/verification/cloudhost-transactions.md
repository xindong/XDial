# 云主机部署事务验收

部署与中断恢复共用 `undoResource`；`Deploy` 是部署状态的唯一写入者，恢复只倒序消费其日志。`Baseline` 保存部署前的资源归属，`WasActive` 保存原服务的运行事实。

约束：

- 在资源可能改变之前，持久化撤销意图并登记补偿，包括最终检查失败和部分成功的步骤。
- 每条撤销命令必须检查退出码；任一步失败就停止，保留目录、备份和恢复记录。
- 恢复每一步可重复执行，成功后再持久化移除其日志项；恢复结束后重新检查服务器再生成计划。
- 提交成功记录之后才清理备份及旧端口；新记录只保留当前端口的归属，旧端口清理是一次尽力执行，不跨部署重试，以免以后删除管理员重新创建的规则。防火墙只撤销记录为本次创建的具体 TCP/UDP 规则，不删除已有规则或猜测旧版本记录的归属。
- 取消覆盖 SSH 通道打开、命令启动及执行；正常取消先终止命令并保留连接以当场撤销，只有超过两秒仍无响应才关闭传输并依靠记录恢复。取消回调及超时回调必须在返回前收尾，不能延迟关闭后续撤销所用的连接。
- sudo 认证输入与命令输入分开，缓存认证也不能把密码写入文件。

| 事件 | 改动前 | 部分改动／检查中 | 提交后 | 撤销中 |
|---|---|---|---|---|
| 正常完成 | 保存意图 | 执行并检查 | 清理备份 | 保存剩余日志 |
| 命令失败 | 停止 | 包含失败步骤在内倒序撤销 | 不回退已提交事务 | 停止并保留记录 |
| 状态写入失败 | 不执行资源改动 | 撤销，保留未确认记录 | 不报告成功 | 不继续消费日志 |
| 正常取消 | 结束通道打开，保留连接 | TERM 终止命令，原连接撤销 | 不改变已提交状态 | 在独立撤销期限内继续 |
| 网络无响应 | 两秒后关闭传输 | 两秒后关闭传输，保留恢复记录 | 不改变已提交状态 | 保留记录，重连恢复 |
| 再次设置 | 重新检查 | 先恢复、再检查和生成计划 | 复用已有代理 | 重复执行尚未确认撤销步骤 |

`core/cloudhost/transaction_test.go` 使用进程内 SSH 服务注入配置检查、状态写入、部分防火墙改动和补偿失败，验证旧代理资源保留、恢复后的重新检查和日志顺序；另覆盖无响应通道取消和 sudo 不消费认证输入的情况。

产品边界仍是显式确认改动清单后部署，HTTPS 验证后保存普通线路。真实云主机和设备网络验收独立于这些故障注入测试。

第二轮对称路径检查：取消由 `interruptOnCancel` 统一持有，状态为打开通道／启动命令／执行命令／取消中／已结束；正常完成停止回调；启动确认前不发送 TERM，避免信号先于进程；取消发送 TERM 并等待命令结束，超时关闭传输，所有返回路径等待正在运行的回调结束。没有重连或自动重试。测试覆盖响应／无响应取消、迟到超时，以及 A→B、复用 B、B→C 时管理员重新占用 A 的规则；旧端口清理成功和失败都不能恢复已放弃的归属。

Linux sudo 路径先用独立 stdin 执行 `sudo -S -v`，再执行 `sudo -n`；不与 `-k` 合用（会禁止更新缓存），并保留共同父 shell 以匹配非 TTY 的凭据时间戳。缓存不消费密码、父进程一致性和真实容器端到端分别验证，认证输入不能进入后续文件内容。

2026-11-21 第二轮验证：`go test -race ./core/cloudhost`、`make public-content-gate go-vet go-build test`、Debug 编译与签名身份校验通过；`scripts/test-cloudhost-e2e.sh ubuntu:24.04` 的 12 项隔离容器测试通过，含密码 sudo、取消回滚、断连恢复、HTTPS 流量、复用和改端口。本轮没有验证真实云主机或真机。

服务生命周期约束：只有创建 `unit` 的事务能执行 `systemctl enable`，该资源的统一撤销负责 disable 和删除。`startService` 只负责运行与监听，不改变已有服务的启动策略。这样移除“启动时修改启动策略”的副作用，不增加 enabled 状态日志。运行状态 × 自启动策略分别覆盖 active/inactive、enabled/disabled；成功时保留原启动策略，启动失败、最终提交失败、取消、中断恢复时还原原运行状态并保留启动策略。新服务创建成功仍开启自启动，失败及恢复由 unit 补偿关闭。

| 服务基线 | 成功 | 启动／提交失败及取消 | 中断恢复 |
|---|---|---|---|
| 已有 active + enabled/disabled | active，原启动策略 | active，原启动策略 | active，原启动策略 |
| 已有 inactive + enabled/disabled | active，原启动策略 | inactive，原启动策略 | inactive，原启动策略 |
| 没有 unit | 创建并 enable，再启动 | stop、disable 并移除新 unit | stop、disable 并移除新 unit |

`TestExistingServiceBootPolicyPreserved` 覆盖全部已有服务组合和终态；Linux 容器额外验证新服务自启动，以及 disabled/inactive 服务改端口失败后的运行／启动策略恢复。此约束由 unit 创建事务和既有 `undoResource` 持有，不散落 enabled 状态判断或新增持久化字段。
