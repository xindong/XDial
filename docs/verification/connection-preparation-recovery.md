# 连接准备阶段的恢复边界

不变量：从用户请求连接到流量验收，临时网络失败均保留同一个连接意图；终止错误或用户断开后，迟到的准备结果不得启动连接。下载失败的展示文本不得泄露资源 URL，但 Go 错误链必须保留可分类的原因。

Android / Linux 的连接意图由共享 Go recovery controller 管理。Apple 的后台连接意图只由已有的 Keychain 启动包及系统按需配置持有；App 不另建轮询器。Apple 启动 operation ID、扩展 generation 分别隔离各自的迟到回调。

| 事件 | App 准备中 | 扩展准备中 | 系统等待恢复 | 已取消 |
|---|---|---|---|---|
| 准备成功 | 提交当前启动 | 检查 generation，再安装网络设置 | 系统重新拉起后准备 | 忽略迟到结果 |
| 临时下载失败 | 启动包携带待准备 Profile，交给扩展 | 保留启动包，向系统报告临时失败 | 保留请求 | 不得恢复请求 |
| 无效规则、认证或证书错误 | 结束启动 | 撤销启动包 | 不再自动连接 | 保持取消 |
| 用户断开 | 失效 operation ID | 失效 generation | 清理启动包并停用按需配置 | 幂等 |
| 网络恢复 | 当前准备继续 | 当前尝试或系统下一次启动继续 | 由系统按需拉起 | 保持取消 |

审计范围同时覆盖 Profile 规则和编译生成规则的下载错误。二者保留 typed cause，外部仅暴露脱敏消息。缓存命中和场景切换仍使用原路径；连接中的缓存专用准备不会转为联网下载。

Apple v4 启动包区分待准备 Profile 与最终配置，旧版本拒绝解释它。待准备数据沿用现有共享 Keychain，不写入系统 VPN 配置或诊断；扩展在安装捕获设置前使用原 Go 规则获取路径。准备过程中取消可能让当前下载完成并写入缓存，但 generation 检查阻止其继续安装网络设置或启动引擎。

自动回归覆盖下载超时、主动取消、无效规则的 Go 分类与脱敏，以及安全启动包往返和撤销策略。锁屏后的系统拉起、断网恢复和真实流量仍须移动真机验收；模拟器构建不能证明这些系统行为。
